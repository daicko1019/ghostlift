# GhostLift — その広告は、需要を作ったのか、数えただけか

**「広告出稿 × 需要の増分」を LLM マルチエージェントで観測する社会シミュレーション**
（AIエージェント社会シミュレーション・ハッカソン提出物）

![二画面リプレイ](demo/dashboard.jpg)

## これは何？

8人のAI消費者（1人ずつが本物のLLM）が2Dの街に住み、口コミを交わしながら自由に動き、
自分の判断で買い物をします。街には店が2軒あります。広告を出す `brandco` と、出さない `rival` です。

ここまでは普通のシミュレーションです。GhostLift が違うのは、**同じ8人を、広告のある世界と
ない世界で同時に走らせる**ところです。

同一シードから同じ人物・同じ初期位置・同じ財布を生成し、LLM のサンプラまで固定してあるので、
**広告が着弾するステップまで2つの世界はビット単位で同一**になります。
step 4 で片方の世界にだけ広告が流れ、そこから世界が分岐する。
その差分は、定義上すべて広告に起因します。

これは**現実の広告主が絶対に手に入れられないデータ**です。
A/Bテストで比べられるのは別々の人の集団であって、同じ人の2つの人生ではないからです。

そして突き合わせると、広告プラットフォームが「広告の成果」として報告するコンバージョンが、
実は4つの別物の寄せ集めだったことが見えます。

| | 意味 | プラットフォームの報告 |
|---|---|---|
| **NEW** | 広告が本当に生んだ購買 | 成果として計上される |
| **STOLEN** | 競合から奪った購買（ブランドには増分、市場には増分ゼロ） | 成果として計上される |
| **GHOST** | 広告がなくても買っていた人の購買 | **成果として計上される（幽霊）** |
| **LOST** | 広告のせいで失われた購買 | **決して計上されない** |

評価観点との対応:

- **二領域をまたぐ連鎖**: 情報（広告配信・ターゲティング）→ 口コミ再拡散 → 来店 → 購買 → 在庫枯渇 → 買えなかった人
- **介入点**: 「同じ予算を、誰に当てるか」。全員配信（B）とリターゲティング（C）の比較がそのまま介入実験
- **創発性**: 台本なしのLLM消費者から、口コミによる又聞き伝播と、広告を見ていない人の来店が観察された
- **技術実装**: 本家が「不可能」と明記していた**実行の再現性**を導入し、反実仮想ペアの実行を可能にした（下記「本家からの差分」）

## クイックスタート

前提: Python 3.8+ / [Ollama](https://ollama.ai/)（ローカルLLM。APIキー不要・無料）

```bash
git clone https://github.com/daicko1019/ghostlift.git
cd ghostlift

# macOS/Linux
python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt

# Windows
#   python -m venv venv && venv\Scripts\activate.bat && pip install -r requirements.txt

# モデル取得（約2.5GB。軽量モデルなのでGPUが無くても動く）
ollama pull qwen3:4b-instruct-2507-q4_K_M
```

3つのシナリオを実行します（1本あたり LLM 呼び出し256回）:

```bash
python scripts/run_all.py
```

3本を同時に走らせて待ち時間を縮められます。Ollama が並列リクエストを1つのGPUバッチに
まとめるため、3倍かかるわけではありません:

```bash
# モデルを常駐させておく（下記の警告を参照）
OLLAMA_KEEP_ALIVE=4h ollama serve

# 別ターミナルで
python scripts/run_all.py --parallel 3
```

**LLMシミュレーションの1回の実行は逸話にすぎません。** シードを変えた複数試行を回して
分布で語るのが本筋です。GPUがあるなら:

```bash
python scripts/run_all.py --seeds 42 43 44 --parallel 3
python scripts/aggregate_trials.py 42 43 44
```

### ⚠️ 冷えたモデルで走らせると比較が壊れる（重要）

**双子ランは、モデルがロード済み（ウォーム）の状態で始めてください。**
`scripts/run_all.py` は最初に捨てリクエストを1本投げて必ずウォームアップします。

モデルのロードを引き起こしたランと、すでに常駐しているモデルに当たったランとでは、
シードを固定していても生成がずれます。**取る行動は変わらない**のですが、
エージェントが発する**口コミの文面と記憶の文面**が変わり、これらは世界に戻るので、
広告を出していないのに2つの世界が分岐します。実際に我々はこれで二度失敗しました。

我々が測った範囲では以下のとおりです（qwen3:4b / Apple M1 / Ollama 0.33）:

| 比較 | 世界の状態 | 口コミ・記憶（世界に戻る） | reasoning（ログのみ） |
|---|---|---|---|
| 同一設定・コールド vs ウォーム | 一致 | **不一致** | 不一致 |
| 同一設定・ウォーム vs ウォーム | 一致 | 一致 | 一致 |
| 広告前の双子・逐次実行 | 一致 | 一致 | **不一致** |
| 広告前の双子・同時実行 | 一致 | 一致 | 一致 |

注目に値するのは、**どの条件でも「世界の状態」（位置・行動・購買・在庫）は一致した**ことです。
temperature 0.2 では意思決定は安定していて、揺れるのは散文だけでした。
とはいえ口コミと記憶は次のプロンプトに入るので、散文の揺れはいずれ行動の差になりえます。
だからウォームアップを必須にしています。

### 検証しているのは「世界」であって「文章」ではない

LLMの出力のうち、次のプロンプトに戻るのは2つだけです。

| フィールド | 行き先 | 比較対象か |
|---|---|---|
| `message` | 近くのエージェントに届き、相手の次のプロンプトに入る | **する** |
| `memory` | 自分の記憶に積まれ、自分の次のプロンプトに入る | **する** |
| `reasoning` | ログに書かれるだけで二度と読まれない | しない |

`reasoning` だけが違う2つのランは、**同じ世界の議事録が2通りある**だけなので、
比較を無効にしません。検証スクリプトはこれを区別し、`reasoning` の差は注記に留めます。

### 「本当に同じ世界なのか」を検証する

この作品の主張は「広告が着弾するまで2つの世界は同一」という一点にかかっています。
主張のままにせず、検証スクリプトを同梱しています:

```bash
python scripts/verify_twins.py output_noad output_broadcast --ad-step 4
```

乖離があれば分解が成立しないので、スクリプトは**非ゼロ終了します**。
実行結果は下記「結果」の節に掲載しています。

実行が終わったら、2つの世界を並べて再生できます:

```bash
python scripts/serve.py
```

→ ブラウザで **http://localhost:8124/demo/dashboard.html** を開いて「▶ 再生」。
左に広告のない世界、右に広告のある世界。同じ番号の点が同じ人物です。
（Space=再生/停止、←→=コマ送り）

> 💡 **まだ実行していなくても見られます**: 実行結果の生ログを `sample_output/` に同梱してあるので、
> clone → `python scripts/serve.py` でサンプル実行の再生が始まります。

## 3つのシナリオで「介入点」を試す

3つの設定ファイルの違いは **`ad_campaigns` ブロックだけ**です。世界も人も財布も在庫もシードも同一。

| シナリオ | 内容 | 実行 |
|---|---|---|
| A 広告なし | 反実仮想。誰も広告を出さない | `python src/main.py --config scenario_noad.yaml` |
| B 全員配信 | 未購入の全員に同じ広告 | `python src/main.py --config scenario_broadcast.yaml` |
| C リターゲティング | 店から半径6以内の人だけに広告 | `python src/main.py --config scenario_retarget.yaml` |

分解の実行:

```bash
python scripts/ghost_analysis.py output_noad output_broadcast output_retarget \
       -o demo/ghost_decomposition.png
```

C が介入実験の本命です。実務のリターゲティングは「効率が良い」とされますが、
それは**もともと買う人に当てているから効率が良く見えるだけ**ではないか、という仮説を
シミュレーションに問わせます。

## 本家からの差分（拡張ポイント）

すべて**省略可能な設定**として追加してあり、同梱の `config.yaml` を実行すれば本家の火事デモがそのまま動きます。

| 拡張 | 内容 | 設計意図 |
|---|---|---|
| `seed` 設定 | 初期位置・性格・予算・LLMサンプラを固定 | **本作品の核心**。本家READMEは「初期位置と性格が毎回ランダムで、シード固定の項目がない」と明記している。反実仮想ペアは同じ人物を突き合わせられないと成立しないので、ここを拡張した |
| `ad_campaigns` 設定 | 指定ステップに、**ターゲティングで決まった相手だけ**へ届く配信イベント | 本家の火事（半径＝距離で決まる局所イベント）の対。同じ「一部の人だけが知る外部ショック」でも、**誰が知るかを決めるのが自然法則か広告主か**が違う |
| `places[].stock` / `price` | 店の在庫と価格。店内の人だけが残数を知れる | 本家の「数値だけ渡して解釈はLLMに委ねる」思想を踏襲 |
| `agents.budgets` | 各エージェントの予算（数値のみ） | 同上。「安い/高い」の判断は書かず、LLMに委ねる |
| `buy` アクション | 店内かつ在庫あり・予算内のときだけ成立。耐久財として1人1回 | 買うかどうかを LLM の判断にすることで、「広告が説得したか」を初めて問える |
| `metrics.jsonl` | 在庫・購買・広告配信・位置を毎ステップ記録 | 分解スクリプトとダッシュボードの入力 |
| `scripts/ghost_analysis.py` | 2つの実行を個人単位で突き合わせ、NEW/STOLEN/GHOST/LOST に分解 | 本作品の主要成果物 |
| `scripts/verify_twins.py` | 広告前の2世界がログレベルで同一であることを検証 | 「差分は広告に起因する」という主張を、主張のままにしないため |
| `demo/dashboard.html` | 2つの世界を並べて再生 | 反実仮想そのものを絵にする。デモ動画もこれ1枚で作れる |

## 解釈上の注意

本シミュレーションの出力は**検証済みの人間行動予測ではありません**。仮説生成のための道具です。

- 掲載した数字は**1回の実行例**であり、統制された評価ではありません。複数回まわして分布を見るのが次の一手です
- ログに現れる情景描写はLLMが生成した内容であって、シミュレータの状態ではありません。
  グリッド上に実在するのは座標・場所・在庫・価格・予算という数値だけです
- 「見かけと実態が N 倍乖離する」という結果は、**この架空の市場における1試行の観測**であって、
  実在の広告媒体の測定精度を示すものではありません
- 本作品は実データを一切使っていません。完全に架空の市場です

詳細は [docs/UPSTREAM_README.ja.md](docs/UPSTREAM_README.ja.md) の「解釈上の注意」を参照してください。

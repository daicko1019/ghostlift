# デモ動画の台本（3分）

提出物③向け。ナレーションなしでも伝わるように、画面の見せ方だけで筋が通る構成にしてある。
音声を入れられるなら「言うこと」の列をそのまま読めばいい。

## 撮る前の準備

```bash
cd ghostlift
python scripts/serve.py
```

ブラウザで <http://localhost:8124/demo/dashboard.html> を開く。

- ブラウザを**全画面**にし、⌘− で**左右の2画面と下の分解表が1画面に収まる**ズームにする
  （収まらない場合は分解表までスクロールする瞬間を1回だけ作る。行ったり来たりはしない）
- 右上のセレクタが **B: broadcast（全員配信）** になっていることを確認
- スライダーを **step 1** に戻しておく
- 録画は Mac なら `shift + ⌘ + 5` →「選択部分を収録」でブラウザ領域だけを囲う

## 構成

| 時間 | 画面 | 操作 | 言うこと／字幕 |
|---|---|---|---|
| 0:00–0:15 | ダッシュボード上部（タイトルが見える状態） | 静止 | 「広告を出すと、コンバージョンが報告されます。でもその数字は、広告が**作った**ものなのか、放っておいても買った人を**数えた**だけなのか」 |
| 0:15–0:40 | 左右の2画面、step 1 | 静止したまま、マウスで左右の同じ番号の点を順に指す | 「左が広告のない世界、右が広告のある世界。**同じ番号の点は同じ人物**です。同じシードから同じ12人・同じ初期位置・同じ財布を生成しているので、この2つは同じ世界の2つの人生です」 |
| 0:40–1:00 | step 1→3 までコマ送り（→キー3回） | ゆっくり3回 | 「広告が流れるまで、2つの世界は完全に同一です。口コミの文面も、各自の記憶も、1文字違いません」 |
| 1:00–1:15 | step 4 へ1コマ | →キー1回。**右側だけ**オレンジのパルスが出る | 「step 4。右の世界にだけ広告が届きます。ここから先の差は、定義上すべて広告に起因します」 |
| 1:15–2:00 | 再生（Space） | 最後まで自動再生 | 「点が店に向かい、買った人は色が変わり、在庫が減っていきます。左右で**誰が買ったかが変わっていく**のが見えます」 |
| 2:00–2:35 | 下の分解表 | 必要ならここでスクロール | 「広告プラットフォームが報告するCVを、1人ずつ突き合わせて4つに分けたものです。**NEW** が広告の生んだ需要、**STOLEN** が競合から奪ったもの、**GHOST** は広告がなくても買っていた人、**LOST** は広告のせいで失われた売上で、これは決して報告されません」 |
| 2:35–2:50 | 同じ画面の最終行 | 「見かけは実態の N 倍」の行をマウスで囲う | 「報告値と実際の純増の比です」 |
| 2:50–3:00 | セレクタを **C: retarget** に切り替え → 再生せず分解表を見せる | セレクタ操作1回 | 「同じ予算を、すでに買う気の人だけに当てた場合。実務で最も使われている打ち方です」 |

## 撮り方のコツ

- **マウスを動かしすぎない。** 指すときだけ動かし、あとは止める。動く点を見せたいのであって、カーソルを見せたいのではない
- コマ送りは1回ずつ**間を置く**。連打すると何が変わったか見えない
- 撮り直しは「step 1 に戻す → 再生」だけでいつでもできる。編集しなくていいように、一発撮りを何度かやるほうが早い
- 3分に収まらなければ 1:15–2:00 の自動再生を途中でスライダーごと飛ばしてよい。**削るのは移動シーンで、分解表は削らない**

## 出し方

- YouTube に**限定公開**でアップ（「非公開」ではない。非公開だと審査員が見られない）
- URL を提出フォームに貼る
- ファイル名は `参加者番号_氏名_GhostLift_動画` の形式、半角英数字で

## 生成済みの動画（画面録画なしで作ったもの）

`demo/ghostlift_demo.mp4`（2分41秒・1920x1080・日本語ナレーション付き）を同梱している。
手で画面録画したものではなく、**素材も音声もプログラムで生成して組んだ**もの。

作り方:

1. ダッシュボードは `#step=N` で任意のステップを表示できるので、headless Chrome で
   24ステップぶんスクリーンショットを撮る（`demo/dashboard.html#step=1` … `#step=24`）
2. 説明スライド（`docs/slides.html`）を8枚の静止画として切り出す
3. 字幕カードを3枚生成する（音声なしでも何を見ればいいか伝わるように）
4. ffmpeg の concat デマクサで、台本どおりの尺で並べる

```bash
python scripts/serve.py          # 別端末で
# 24ステップぶんのコマ撮り
for i in $(seq 1 24); do
  chrome --headless --window-size=1600,1080 --virtual-time-budget=3500 \
    --screenshot="frames/dash_$(printf %03d $i).png" \
    "http://localhost:8124/demo/dashboard.html#step=$i"
done
```

再生時間の配分は、`step 4`（広告着弾）を5秒、広告前の3ステップを各2.4秒と長めに取り、
中盤以降を1.6秒に詰めてある。**左右が同一であることを見せる時間**と、
**分岐が起きる瞬間**にだけ尺を使う設計。

### AKARI Video で仕上げる場合

`~/Akari/channels/my-channel/videos/2026-08-30-ghostlift/` にプロジェクトを作ってある。

```bash
cd ~/Akari/channels/my-channel/videos/2026-08-30-ghostlift
akari.sh                 # 編集エージェントを起動
akari.sh --preview       # 別端末でプレビュー
```

`edit.json` が編集の正本で、上記の mp4 を1本のカットとして置いてある。
ナレーション（VOICEVOX）・BGM・オーバーレイを足す土台として使える。

### ナレーション

[Irodori-TTS](https://huggingface.co/Aratako/Irodori-TTS-v4.1-Small) v4.1-Small で13本を生成した
（Apple M1 / MPS、`num_steps=16`、参照音声なしのキャプション指定のみ）。台本は
`demo/narration/script.json`、生成結果の尺は `demo/narration/manifest.json` にある。

**尺は音声側が決めている。** 映像に合わせて読ませると早口になるので、自然長で生成してから
各カットの表示時間をナレーション長 + 前後の間で決めた。ナレーションの無いカットだけ固定尺。

モデルのロードに約60秒かかるため、1本ずつ呼ばずに**1プロセスで13本まとめて生成**している
（`batch_ghostlift.py` 相当）。13本・498字で合計111.6秒、生成に約10分。

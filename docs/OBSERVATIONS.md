# 観測記録

シミュレーションを作る過程で出てきた、書き残す価値のある挙動。
いずれも設計の失敗から見つかったもので、成功例の展示ではない。

---

## 1. 存在しないルールを幻覚し、自分の記憶を通じて自己強化する

初期設計（世界が広く、店内での購入可否をプロンプトに明示していなかった版）の
`noad` / seed 43 で観測。12人中ただ1人だけ入店できた agent 8 が、
**存在しないルールを発明して行動不能になった。**

エージェントの `memory` フィールドの推移:

| step | memory（抜粋） |
|---|---|
| 6 | 「Agent 9 と落ち合うため brandco の入口へ向かう。**two-agent purchase rule** を満たすには一緒に到着する必要がある」 |
| 7 | 「入口にいる。Agent 9 はまもなく来る。**購入には二人とも居合わせる必要がある**。在庫4個・$5、合計予算なら3個まで買える」 |
| 8 | 「**two-agent purchase rule は有効**であり、取引を確定するには自分がここに留まらねばならない」 |
| 9–12 | 「**two-agent purchase rule は取引に両者の同席を要求する**」（以降ほぼ同文で反復） |

シミュレータにそのようなルールは無い。`buy` は「店内・在庫あり・予算内」の3条件だけで成立する。
それでもこのエージェントは、買える在庫4個の店に立ったまま**11ステップ以上、一度も買わなかった。**

### なぜ自己強化するのか

本家の設計では、LLMが出力した `memory` はそのまま自分の次のプロンプトに入る。
つまり **1ステップ目の幻覚が、2ステップ目には「前提」として与えられる**。
上の表で「まもなく来る」→「ルールは有効」→「両者の同席を要求する」と
推測が断定へ硬化していくのは、この帰還経路の産物である。

外部からの訂正が入らない限り、エージェントは自分の作り話の中に閉じ込められる。

### 対処

プロンプトの沈黙が幻覚の余地を作っていた。店内にいて購入が成立する状態のとき、
それを事実として明示するようにした（`src/agent.py` の `_build_stock_section`）。

```
  Units left in stock here: 4
  Price per unit: 5
  A purchase here is possible on this step: price 5, your budget 8.
  No other condition applies.
```

「買え」とは言っていない。**買えるという事実を述べているだけ**で、
判断は引き続きLLMに委ねている。本家の「数値だけ渡して解釈は委ねる」流儀を保ったまま、
発明された前提条件を潰す形にした。

あわせて `AVAILABLE ACTIONS` の文言も「Only possible while...」から
「Possible exactly when ... There are no other requirements.」へ変えた。

### 示唆

LLMエージェントの社会シミュレーションでは、**プロンプトに書かれていない領域が
そのまま創発の余地になる**。それは面白い創発を生むこともあれば、
このように観測を台無しにする作り話を生むこともある。
どちらが起きるかは事前には分からないので、**観測したい変数に直結する条件は
明示しておくほうがよい**、というのが今回の教訓。

## 2. 世界の広さが、観測したい現象そのものを消す

同じ初期設計で、**264 agent-step のうち店内にいたのはわずか 17**、
しかもその全部が agent 8 ひとりのものだった。12人中11人が22ステップかけて
一度も入店していない。

移動は1ステップ1マスで、フィールドは21×21、店は中心から7マス離れていた。
ランダムな初期位置から店に着くまでに10ステップ前後かかり、
そこから購入判断に至る前にシミュレーションが終わる。

購買がほとんど起きないので、広告あり/なしを比べても**両方ほぼゼロ**にしかならず、
分解の4分類が空になる。世界の広さという、一見すると本質でないパラメータが、
観測したい現象の有無を決めていた。

フィールドを15×15、店を中心から4マスへ寄せたところ、
**12ステップで購買5件**（修正前は22ステップで0〜3件）まで改善した。

### 示唆

本家のHOWTOにも「空間が広すぎるかも。移動は1マス/ステップなので、
ステップ数内に目的地へ届く広さにする」という注意がある。
これは単なるチューニングの話ではなく、**観測対象が発生する条件を確保する**という
設計上の必須事項として扱ったほうがよい。

## 3. 反実仮想ペアは、いつも成立するわけではない

**この作品の設計上いちばん重要な発見。** 同一シード・同一モデル（digest 一致）・同一コードでも、
広告を出す前から2つの世界が分岐することがある。

16ペアを `scripts/verify_twins.py` で検証した結果:

| 実行 | ノード | Ollama | 結果 |
|---|---|---|---|
| seed 44 | honda-4070ti | 0.33.2 | ✅ 4ペアすべて、行動も口コミ本文も完全一致 |
| seed 42 | aipc3090 | 0.20.7 | ❌ 口コミ本文が相違 |
| seed 43 | kondo-4070ti | 0.33.1 | ❌ 位置が相違 |
| seed 42（honda で再実行） | honda-4070ti | 0.33.2 | ❌ step 3 で agent 1 が別の店に立った |
| seed 43（honda で再実行） | honda-4070ti | 0.33.2 | ❌ 口コミ本文が相違 |

最後の2行が決定的だった。**検証を通った honda でも、シードを変えると壊れる**（3シード中1勝2敗）。
つまり原因はノードだけではない。

### なぜか

temperature 0.2 では大半のトークンは実質的に一意に決まる。しかし候補が拮抗する場面では、
GPU の浮動小数点の丸め順序のわずかな差で選択が反転する。それが起きるかどうかは初期条件しだいで、
**seed 44 が通ったことには幸運が含まれている。**

一度反転すると後戻りできない。エージェントの `message` と `memory` は次のプロンプトに戻るので、
1トークンの差が次のステップの行動を変え、そこから世界が分岐していく。

### どう扱ったか

「常に厳密再現できる」とは主張しない。**「厳密再現できたケースだけを選んで増分を測る」**という運用にした。

- 検証を通らなかった実行は、数字を一切出さずに破棄した（4シードぶんのGPU時間を捨てた）
- 検証スクリプトを同梱し、README に合否の表を載せた
- 検証を通った実行だけを結果として掲載した

### 示唆

分散環境でLLMマルチエージェントの反実仮想を測ろうとする人は、必ずここを踏む。
**「同じシードを指定したから同じ世界だ」という前提は、検証しない限り成り立たない。**
そして検証は安い。ログを突き合わせるだけで済む。

## 4. コールドスタートは、行動ではなく「言葉」を変える

詳細は README の「冷えたモデルで走らせると比較が壊れる」を参照。要点だけ:

モデルのロードを引き起こしたランと、常駐済みのモデルに当たったランでは、
シードを固定しても生成がずれる。ただしずれ方に構造がある。

| 揺れたもの | 世界に戻るか |
|---|---|
| 位置・行動・購買・在庫 | **一度も揺れなかった** |
| 口コミ・記憶の文面 | 揺れる。**次のプロンプトに戻る** |
| reasoning の文面 | 揺れる。ログにしか残らない |

temperature 0.2 では意思決定は安定しており、揺れるのは散文である。
とはいえ口コミと記憶は世界に帰還するので、放置すればいずれ行動の差になる。

この現象は **Apple M1 / Ollama 0.33.2** と **RTX 3090 / Ollama 0.20.7** の
両方で再現した。ハードウェアもバージョンも違う環境で同じ挙動が出たので、
特定環境の癖ではないと考えている。
